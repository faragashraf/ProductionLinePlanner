# 04 - نطاق Frontend (Angular + PrimeNG)

## مسؤوليات Frontend الأساسية
- عرض خريطة الإنتاج بطريقة سريعة وسهلة على الموبايل.
- تنفيذ واجهات إدارة الخطوط والمراحل والعمال.
- تمكين drag & drop للتعيين المؤقت.
- استهلاك API وSignalR.
- إدارة القراءة/غير المقروء للإشعارات.
- توفير تنقل واضح عبر sidebar وbreadcrumb.

## هيكل الشاشات MVP
1. **تسجيل الدخول + Guard**.
2. **لوحة المصنع (Factory Map)**
   - خطوط.
   - مراحل رئيسية/فرعية.
   - مؤشرات جاهزية.
3. **إدارة العمال**
   - تعيين ثابت.
   - تبديل مؤقت.
4. **الإشعارات**
   - read/unread.
   - وضع فلترة/نوع/وقت.
5. **الإعدادات** (Super Admin)
   - أدوار.
   - سياسات.

## مكونات UI الأساسية
- `HeaderBar` مختصر للموبايل.
- `ResponsiveSidebar` (قابل للطي/الفتح).
- `Breadcrumb` محدث بناءً على المسار الحالي.
- `FactoryLineCard` لكل خط إنتاج.
- `StageChip` / `WorkerPill` للحالة البصرية.
- `ReadinessMeter` لعرض النسبة.
- `AssignmentDragCanvas` للحركات المؤقتة.
- `NotificationPanel` ثابت أو منزلق.

## مبدأ Mobile-first
- تصميم بحجم لمسة كبيرة.
- أزرار أساسية بارزة.
- قوائم متدرجة بدل الجداول الثقيلة في بداية التصميم.
- دعم وضع landscape بشكل مرن.

## إدارة الحالة
- State للخلفية:
  - Auth state (صاحب الدور، الصلاحيات).
  - Map state (خطوط/مراحل/عمال).
  - Notification state.
- SignalR:
  - إعادة مزامنة العناصر المتغيرة فقط.
  - تجنب إعادة تحميل كامل الصفحة عند كل event.

## UX للحالات اللونية
- بطاقة العامل/المرحلة تحمل indicator.
- Green = جاهز.
- Red = غير متوفر/غائب.
- Yellow = متأخر/تحذير.

## حماية الواجهات
- Generic Auth Guard:
  - توجيه غير المصرح لهم إلى شاشة الدخول/خطأ.
- Route-based checks من الدور.

## أسئلة مفتوحة
- هل نحتاج وضع “مراقبة شاشة كبيرة” مخصص للتابلت أم نكتفي بتوزيع متجاوب؟
- هل سيتم تدعيم drag & drop بعرض بديل على اللمس القديم/البطئ؟
- هل نحتاج وضع Offline Read مع بيانات مؤقتة محلية؟
