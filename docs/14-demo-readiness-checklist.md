# قائمة جاهزية الديمو الداخلي الأول

## 1. هدف جاهزية الديمو

الهدف من هذه القائمة هو اتخاذ قرار واضح قبل كل ديمو داخلي: هل النظام جاهز للعرض أم يجب إيقاف الديمو ومعالجة العوائق أولا؟

تستخدم هذه القائمة قبل الديمو الداخلي الأول لمشروع Factory Planner / Production Line Planner، وتركز فقط على السيناريو العملي المتوقع عرضه: تسجيل الدخول، عرض لوحة التحكم، خريطة المصنع، اختيار مرحلة بها نقص، فتح شاشة الإسناد، عرض أفضل بديل، ومحاكاة قرار الإسناد.

قرار الجاهزية يجب أن يكون واحدا من التالي:

- [ ] جاهز للديمو.
- [ ] جاهز مع تحذيرات مقبولة.
- [ ] غير جاهز ويجب إيقاف الديمو.

## 2. بوابات الديمو

### Gate 1: جاهزية البناء

- [ ] بناء backend يكتمل بدون أخطاء.
- [ ] بناء frontend production يكتمل بدون أخطاء.
- [ ] لا توجد تغييرات مؤقتة أو ملفات تجريبية مطلوبة لتشغيل الديمو.
- [ ] نسخة الديمو تعمل من الفرع المحدد للديمو.

قرار البوابة:

- [ ] اجتياز.
- [ ] تحذير.
- [ ] فشل.

### Gate 2: جاهزية البنية والتشغيل

- [ ] قاعدة بيانات التطبيق متاحة.
- [ ] قاعدة بيانات الحضور متاحة أو تم تجهيز بيانات بديلة للديمو.
- [ ] إعدادات التشغيل المحلية مكتملة.
- [ ] مفاتيح التشغيل الحساسة موجودة في User Secrets أو البيئة المحلية.
- [ ] backend يعمل على الرابط المحلي المتفق عليه.
- [ ] frontend يعمل على الرابط المحلي المتفق عليه.

قرار البوابة:

- [ ] اجتياز.
- [ ] تحذير.
- [ ] فشل.

### Gate 3: الجاهزية الوظيفية

- [ ] تسجيل الدخول يعمل بحساب الديمو.
- [ ] لوحة التحكم تعرض بيانات مفهومة.
- [ ] خريطة المصنع تعرض المراحل المطلوبة للديمو.
- [ ] شاشة الإسناد تفتح من مرحلة بها نقص.
- [ ] توصية أفضل بديل تظهر بوضوح.
- [ ] مؤشرات الجاهزية تظهر بعد محاكاة الإسناد.

قرار البوابة:

- [ ] اجتياز.
- [ ] تحذير.
- [ ] فشل.

### Gate 4: جاهزية تجربة المستخدم

- [ ] الواجهة عربية في الشاشات المعروضة.
- [ ] الاتجاه RTL واضح ولا يكسر التخطيط.
- [ ] الأزرار والحقول قابلة للاستخدام على laptop وtablet وmobile.
- [ ] حالات التحميل والفراغ والخطأ مفهومة.
- [ ] لا يوجد overflow أفقي في الشاشات الرئيسية.

قرار البوابة:

- [ ] اجتياز.
- [ ] تحذير.
- [ ] فشل.

### Gate 5: جاهزية العرض

- [ ] مسار الديمو تم تجربته مرة كاملة قبل العرض.
- [ ] بيانات الديمو مناسبة ولا تحتوي معلومات حساسة.
- [ ] يوجد سيناريو كلامي مختصر لكل شاشة.
- [ ] يوجد خطة بديلة إذا تعطل جزء من النظام.
- [ ] تم تحديد شخص مسؤول عن تشغيل الديمو وشخص مسؤول عن تسجيل الملاحظات.

قرار البوابة:

- [ ] اجتياز.
- [ ] تحذير.
- [ ] فشل.

## 8. درجة الديمو

طريقة الحساب:

- كل بند حرج جاهز = 2 نقطة.
- كل بند تحذيري جاهز = 1 نقطة.
- كل بند بحالة تحذير = نصف نقاطه.
- كل بند فاشل = 0 نقطة.
- نسبة الجاهزية = النقاط المحققة ÷ إجمالي النقاط الممكنة × 100.

قواعد القرار:

- أي فشل في بند حرج يمنع الديمو حتى لو كانت النسبة مرتفعة.
- البنود التحذيرية لا تمنع الديمو تلقائيا، لكنها تخفض النتيجة وتحتاج قرارا واعيا من مسؤول الديمو.
- ديمو بنسبة أقل من 85% يعتبر غير جاهز.
- ديمو بنسبة 85% إلى 94% يعتبر جاهزا مع تحذيرات.
- ديمو بنسبة 95% أو أكثر يعتبر جاهزا.

## 10. العوائق وقواعد الإيقاف

يجب إيقاف الديمو إذا حدث أي مما يلي:

- [ ] فشل تسجيل الدخول بحساب الديمو.
- [ ] backend لا يعمل أو health endpoint لا يستجيب.
- [ ] frontend لا يفتح أو لا يمكن التنقل داخله.
- [ ] شاشة خريطة المصنع لا تعرض بيانات الديمو.
- [ ] شاشة الإسناد لا تفتح من مرحلة النقص.
- [ ] توصية البديل لا تظهر.
- [ ] توجد أسرار حقيقية ظاهرة في ملفات أو رسائل خطأ أو واجهة المستخدم.
- [ ] يوجد خطأ مرئي يمنع إكمال مسار الديمو الأساسي.

يمكن الاستمرار مع تحذير إذا حدث أي مما يلي:

- [ ] تأخر تحميل بسيط لا يمنع المسار.
- [ ] تنسيق غير مثالي في شاشة غير أساسية.
- [ ] رسالة خطأ قابلة للشرح ولا تؤثر على مسار الديمو.
- [ ] نقص في تنبيه أو مؤشر ثانوي.

قرار الإيقاف:

- [ ] الاستمرار.
- [ ] الاستمرار مع توضيح للمشاركين.
- [ ] إيقاف الديمو.

## 11. خطة بديلة

إذا تعطل جزء من النظام أثناء التحضير أو العرض:

- [ ] إعادة تشغيل backend مرة واحدة فقط قبل قرار الإيقاف.
- [ ] إعادة تحميل frontend مرة واحدة فقط إذا كانت المشكلة مؤقتة.
- [ ] استخدام بيانات ديمو بديلة إذا كانت قاعدة الحضور غير متاحة.
- [ ] عرض screenshots حديثة فقط إذا كان الهدف توضيح التدفق وليس إثبات التشغيل الحي.
- [ ] الانتقال إلى شرح شفهي قصير للمسار المتعطل مع تسجيله كعائق.
- [ ] إنهاء الديمو مبكرا إذا تعطل المسار الأساسي: login، dashboard، factory map، assignment، recommendation.
