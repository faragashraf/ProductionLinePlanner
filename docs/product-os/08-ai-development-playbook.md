# AI Development Playbook

## Model Selection Policy

اختيار النموذج قرار تشغيلي مبني على نطاق المهمة، مستوى المخاطر، والحاجة إلى مراجعة معمقة. لا يغيّر استخدام AI المسؤولية البشرية عن Definition of Done، المراجعة، أو الـ Checkpoint.

| النموذج | متى يُستخدم | لا يُستخدم عندما |
| --- | --- | --- |
| `GPT-5.3-Codex-Spark` عبر CLI | مهمة تنفيذ أو توثيق واضحة، محدودة النطاق، وقابلة للتحقق؛ إصلاح مباشر أو بناء محدد ضمن DoD. | القرار يحتاج مفاضلة معمارية عميقة أو مراجعة أمنية حساسة. يُتجنب في Desktop عند ظهور مشكلة `reasoning.summary`. |
| `GPT-5.6 Terra` | مراجعة متوازنة قوية للـ backend/refactor، صلاحيات وأمان، تحليل أثر متعدد capabilities، والتحقق قبل Checkpoint. | التغييرات الخفيفة جدًا التي لا تستحق تكلفة التحليل. |
| `GPT-5.5` أو `GPT-5.6 Sol` | visual QA، إنقاذ UX، إعادة تصميم حساسة، أو قرارات معمارية معقدة. | الأعمال التنفيذية الروتينية محدودة النطاق. |
| `GPT-5.6 Luna` | فحص سريع، صياغة خفيفة، أو مهمة منخفضة المخاطر ومحدودة جدًا. | التنفيذ الذي يغير قواعد الأعمال أو الأمان أو البيانات. |

## Spark: Development

- ينفذ capability أو جزءًا منها عندما يكون النطاق وDoD معروفين.
- يكتب مسودة التوثيق، الاختبارات، أو الإصلاحات المباشرة، ثم يثبت نتائج التحقق.
- لا يتجاوز Architecture Review ولا يقرر إغلاق ملاحظة `Critical` أو `High` بمفرده.

## Terra: Review and Validation

- يراجع الحدود المعمارية، عدم تكرار منطق الأعمال، أثر البيانات، والصلاحيات.
- يستخدم للمراجعة قبل Checkpoint، ولـ hardening المتقدم وتحليل trade-offs.
- يعيد الملاحظات إلى التنفيذ بصياغة قابلة للقياس، ثم يتحقق من الإغلاق.

## قواعد التصعيد

- الافتراضي هو النموذج الأخف الذي يحقق DoD دون تقليل مستوى التحقق.
- التصعيد إلى `Terra` إلزامي عند وجود تغيير في authorization، نموذج بيانات أساسي، أو مخاطرة تتجاوز `Low`.
- التصعيد إلى `Sol` إلزامي عند احتياج visual QA أو UX rescue جوهري.
- يُسجل اختيار غير اعتيادي للنموذج وسببه في ملف capability أو [Decision Log](12-decision-log.md).
