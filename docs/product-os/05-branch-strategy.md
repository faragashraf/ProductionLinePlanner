# Branch Strategy

## البنية المقترحة للفروع

- `architecture/*`
  - تغييرات الأصول المعمارية/تصميمية.
  - تستخدم قبل التنفيذ عندما يكون هناك أثر بنيوي على architecture أو integration.

- `feature/*`
  - تنفيذ الميزات التجارية العادية.
  - لا تُستخدم للـ hardening أو الإصلاح الحرجي.

- `docs/*`
  - تحديثات وثائقية (Product Bible, Product OS, ADRs, runbooks).
  - يمكن الدمج بعد مراجعة peer + محتوى مكتمل.

- `hardening/*`
  - تعديلات الأمن، الأداء، الموثوقية بعد إغلاق التنفيذ الأساسي.
  - يجب أن تكون مرتبطة بتاريخ capability مرجعية.

- `hotfix/*`
  - إصلاحات عاجلة لمشاكل production.
- تُستخدم فقط مع نطاق واضح ومحدد، مع توثيق سبب الطوارئ وPlan-backfill.

## قواعد الدمج

- أي branch يجب أن يمر عبر PR + checkpoint قبل الدمج.
- hotfix لا يتجاوز hardening إذا كان يحمل أثر أمني.
- docs-only branch يمكن دمجها بعد Review سريع إذا لم تُدخل تغييرات سلوكية.
