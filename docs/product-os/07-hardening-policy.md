# Hardening Policy

## مستويات الخطورة

### Critical
- ثغرة أمنية تؤدي لكشف غير مصرح أو تعديل غير مصرح بالبيانات.
- خلل يسبب فقد/تلف بيانات أو تعطيل كامل لمسار أعمال أساسي.
- **تمنع Merge نهائياً** حتى إصلاح جذري وإعادة Validation.

### High
- ضعف أمني يمكن استغلاله محدود النطاق أو تعطل جزئي لمسار أساسي.
- أخطاء منطقية تؤدي لإنتاج بيانات غير صحيحة بشكل منتظم.
- **تمنع Merge** حتى إصلاح ضمن نفس أو أول PR مكمل مرتبط.

### Medium
- أخطاء قابلة للتنفيذ تؤثر على كفاءة/ثبات/تجربة مستخدم حرجة.
- مشاكل غير حاسمة في تغطية tests أو observability.
- يسمح Merge إذا كانت التعديلات الأساسية مكتملة وموثقة مع خطة hardening خلال sprint الحالي.

### Low
- مشاكل تحسينات، تنسيقات غير مثالية، تحسينات أداء بسيطة.
- يمكن Merge مع توثيقها كسيناريو تحسين قادم.

## متى يمنع الـ Merge

- أي وجود `Critical` أو `High` نشط.
- وجود أخطاء أمنية غير مصححة في نفس scope capability.
- نقص في التحقق المرتبط بقسم checkpoint.
