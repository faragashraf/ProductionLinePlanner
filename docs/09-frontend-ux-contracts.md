# 09 - Frontend UX Contracts (مستند واجهات المستخدم)

## نظرة عامة على النطاق

هذا المستند يوثّق **اتفاقية واجهات وتجربة المستخدم (Frontend UX Contracts)** لـ Production Line Planner مع الالتزام الكامل بالعربات الوصفية التالية:
- لا يتم إنتاج أي كود تطبيقي.
- Markdown فقط.
- لا Angular project.
- لا components.
- لا CSS.
- لا .NET.
- لا migrations.
- لا connection strings.

## 1) مبادئ تصميم Mobile-first UX

- الاعتماد على شبكة بطولية بسيطة: `mobile -> tablet -> desktop`.
- عرض العناصر الأساسية أولًا: حالة الخط، جاهزية المصنع، إجراءات العمل الشائعة.
- تجنب الكتل الكبيرة على الشاشات الصغيرة.
- الأزرار تفاعلية بحجم لمس مناسب مع هوامش أمان.
- كل شاشة تعمل بوضوح في وضع Portrait وLandscape.
- تقليل القفز في البنية (reflow) عبر:
  - تجميع المحتوى وفق الأولوية: `الأعلى قيمة/الأكثر تكرارًا أولًا`.
  - فتح تفاصيل إضافية ضمن bottom sheet أو expandable sections.
- إظهار حالة التحميل والخطأ/التحقق بشكل غير معيق:
  - شريط حالة علوي صغير.
  - placeholder واضح بدل الشاشة البيضاء.

## 2) Mobile UX

### 2.1 هيكل الشاشات
- Header ثابت خفيف (عنوان + إشعارات + اسم المستخدم).
- Sidebar بشكل overlay أو drawer.
- المحتوى الأساسي في قائمة عمودية يمكن تمريرها.

### 2.2 السلوكيات
- التنقل الرئيسي من القائمة الجانبية أو bottom tabs حسب الشاشة.
- عمليات تعيين/نقل العامل تكون:
  - خطوة سريعة (اختيار عامل + اختيار مرحلة).
  - تأكيد بصري سريع قبل الإرسال.
- البطـاقـات:
  - عرض مضغوط (compact)
  - سلوك expand لعرض تفاصيل المرحلة/العامل.

### 2.3 قيود اللمس
- لا يعتمد UX على Hover.
- لا أكثر من action مزدوج على نفس العنصر دون رسالة توضيحية.
- أي Drag & Drop يُقدَّم كخيار بديل touch-safe على الموبايل (أزرار تحويل/اختيار).

## 3) Tablet UX

- زيادة كثافة المعلومات ضمن نفس الشاشة مقارنة بالموبايل.
- خريطة المصنع تظهر على مساحة أكبر مع تقسيم منطقي:
  - جزء أعلى: مؤشرات المختصرات (readiness، غياب، تنبيهات).
  - جزء أسفل: تفاصيل المراحل والعاملين.
- sidebar نصف ثابت (docked on wide tablets) مع إمكان الإغلاق.
- عناصر التحكم الأساسية ظاهرة دائمًا:
  - تصفية المصانع/الخطوط.
  - زر تحديث سريع.
  - عداد الإشعارات.

## 4) Laptop/Desktop UX

- layout متعدد الأعمدة:
  - عمود تنقل دائم.
  - عمود محتوى مركزي للخريطة.
  - عمود معلومات/إجراء context أو preview.
- دعم حالات المقارنة side-by-side (Factory line × Stage details).
- يمكن عرض خرائط الإنتاج كاملة مع تفاصيل أكثر لكل stage في نفس الشاشة.
- اختصارات لوحة مفاتيح للأدوار الإدارية المتكررة (على شاشة كبيرة فقط).

## 5) خيارات مكونات PrimeNG

> الهدف توحيد المظهر وتقليل تكلفة التطوير مستقبلاً.

| المجال | المكون المقترح من PrimeNG | ملاحظات الاستخدام |
|---|---|---|
| جدول/قائمة عاملين | `DataTable`/`Table` مع pagination | استخدم في Desktop فقط؛ وفي Mobile يفضّل تبويب البطاقة بدل الصف الافتراضي.
| قائمة العناصر | `Listbox` أو `List` | اختيار سريع للمراحل/الخطوط.
| نوافذ التأكيد | `Dialog` | للحوار المؤقت، تبديل العامل، تفاصيل التحذير.
| قوائم منسدلة | `Dropdown`/`Select` | اختيار نوع الخط، نوع الإشعار، الحالة.
| شارت جاهزية | `Card` + `ProgressBar` | عرض readiness بشكل واضح.
| شريط التنقل | `Menubar` أو `Breadcrumb` | حسب النمط المختار لكل شاشة.
| رسائل حالة | `Toast` + `Message` | للتنبيه الفوري لعمليات التعيين.
| شات/دردشة إشعارات | `OverlayPanel` أو `Panel` | مركز إشعارات context متقدم.
| عناصر إدخال زمنية | `Calendar`/`DatePicker` | بداية/نهاية التعيين المؤقت.
| أزرار | `Button` و `SplitButton` | Actions رئيسية وإجراءات إضافية.

## 6) Responsive Sidebar

- Mobile: sidebar = Drawer overlay، يُفتح ويُغلق بسرعة، ويغلق تلقائيًا بعد اختيار عنصر.
- Tablet: sidebar أقرب إلى pinned (قابل الطي) للحفاظ على المساحة.
- Desktop: sidebar ثابت مع اختصار collapse/expand.

القواعد:
- عناصر التنقل مرتبة وفق تدفق العمل:
  - Dashboard
  - Factory Map
  - Lines & Stages
  - Workers
  - Notifications
  - Settings (حسب الصلاحية)
- تمييز بصري للخطوة الحالية `active route`.
- زر إغلاق واضح في الشاشات التي تكون overlay.

## 7) Dynamic Breadcrumb

- breadcrumb يُحدَّث وفق المسار + المعنى الوظيفي (بديل path-only).
- أمثلة سلوكية:
  - `المصنع > خط الإنتاج 1 > المرحلة 3 > تفاصيل المرحلة`
  - `الإشعارات > غير مقروءة`
  - `العاملون > تعيين مؤقت`
- كل عنصر breadcrumb ينقلك لنقطة سياقية، مع fallback إلى route title عند فقدان الاسم.
- على الشاشة الضيقة، يمكن compressing/تدوير العناصر مع عرض أهم عنصرين بشكل واضح وزر overflow للتوسع.

## 8) شاشة تسجيل الدخول (Login Screen)

- حقول:
  - Email / Username.
  - Password.
  - زر تسجيل دخول.
- حالات رسائل:
  - أخطاء التحقق فورية تحت الحقل.
  - رسالة موحدة عند فشل المصادقة.
- خيارات إضافية:
  - تفعيل/تعطيل `remember me`.
  - عرض حالة الاتصال/السيرفر.
- تجربة ما بعد الدخول:
  - حفظ token في مخزن session آمن.
  - إعادة توجيه تلقائي إلى آخر شاشة مصرح بها.
  - إعادة التحقق من الدور قبل عرض أي مسار.

## 9) Dashboard

- يجب أن يكون أول نقطة مرجعية بعد الدخول.
- مؤشرات Top cards:
  - نسبة جاهزية المصنع.
  - عدد العمال الحاضرين / المتأخرين / الغائبين.
  - عدد الإشعارات غير المقروءة.
  - حالات الخطر الحرجة (critical alerts).
- مخطط زمني سريع (sparkline/summary trend) إذا أمكن ضمن مساحة مخصصة.
- أزرار تنسيق سريع:
  - تحديث الحالة.
  - إعادة تحميل الإشعارات.
  - الذهاب لصفحة خط محدد.

## 10) Factory Map

- تمثيل هرمي للمصنع:
  - خطوط إنتاج.
  - كل خط يحتوي main stages + sub stages.
- واجهة map تضيف قراءة context:
  - اسم الخط.
  - readiness الحالي.
  - تعداد سريع للعمال.
- دعم التمرير الذكي:
  - تكبير افتراضي مناسب لكل stage count.
- أحداث التفاعل:
  - tap/click لفتح Stage details.
  - إبراز خط مختار عبر لون/حاشية.

## 11) Production Line Map

- كل line يعرض:
  - تسلسل المراحل.
  - حالة كل مرحلة رئيسية.
  - حالة capacity/مطلوب حالياً.
- ترتيب المراحل ثابت من المصدر المعرّف في backend، مع إمكانية قراءة اسم المرحلة بوضوح.
- عند وجود مرحلة حرجة: علامة status واضحة (warning icon + badge).

## 12) Stage Details

- تفاصيل مرحلة فرعية تظهر:
  - عدد مطلوب من العمال.
  - عدد الحالي الحاضر.
  - المتأخر.
  - الغائب.
  - نسبة الاستكمال.
- قوائم العمال المخصصين:
  - `ثابت` + `مؤقت` + `بديل`.
- أزرار سريعة:
  - عرض التبديل.
  - إضافة تعيين مؤقت.
  - إلغاء تعيين مؤقت.
- قسم logs مختصر آخر التغييرات على هذه المرحلة.

## 13) Worker Cards

- بطاقة العامل تعرض:
  - الاسم.
  - الكود.
  - الحالة (Ready/Present/late/absent) عبر ألوان الحالة.
  - نوع التعيين (ثابت/مؤقت/بديل).
  - آخر نشاط.
- حالة البطاقة:
  - لون الخلفية/الطرف وفق status semantics أدناه.
- أفعال البطاقة:
  - عرض تفاصيل العامل.
  - تحويل سريع (حسب الصلاحية).
  - فتح الحوار المؤقت.

## 14) Drag and Drop Assignment

- Desktop-first interaction مع دعم fallback للموبايل.
- سلوك أساسي:
  - سحب عامل من بطاقة/قائمة -> إسقاطها في منطقة stage.
  - تحقق تفاعلي قبل تأكيد الحركة.
- سلوك بديل للموبايل:
  - اختيار من-stage worker -> زر Move -> اختيار destination.
- Validation قبل التنفيذ:
  - لا تعيين متداخل لنفس العامل داخل نفس interval.
  - احترام قدرة المرحلة ووجود بدائل.
- feedback:
  - highlight منطقة الإيداع المقبولة.
  - رسالة نجاح فوري مع إمكانية undo إذا كان ذلك مناسبًا.

## 15) Temporary Assignment Dialog

- مكوّن حواري لإنشاء/تعديل/إلغاء تعيين مؤقت:
  - الحقل `من مرحلة` (مقترح تلقائي إذا كانت الحركة من assignment الحالي).
  - الحقل `إلى مرحلة`.
  - `وقت البدء` و`وقت الانتهاء`.
  - سبب التعيين (اختياري/مطلوب حسب السياسة).
- قواعد سريعة داخل الواجهة:
  - تحذير إن كانت نهاية الفترة قبل البداية.
  - تحذير إن تداخل مع تعيين فعّال آخر.
- أزرار:
  - حفظ.
  - إلغاء.
  - حذف التعيين (إذا كانت حالة draft/edit).

## 16) Replacement Worker Flow

- حالة الغياب/التأخير تُظهر زر `تغطية` ضمن Stage details.
- تدفق التغطية:
  1. اختيار العامل المفقود.
  2. اقتراح بديل مناسب وفق الصلاحيات وحالة التوفر.
  3. تحديد نطاق التغطية `from-to`.
  4. تأكيد السبب.
  5. عرض أثر التغيير على readiness.
- في حال فشل الإسناد:
  - رسالة سبب واضح (عامل غير متاح / تداخل / غير مصرح).
- عرض زر `استرجاع` إلى التعين الأساسي إذا انتهت تغطية بديل.

## 17) Notification Center

- نافذة أو panel سياقي ثابت/منبثق.
- فئات الإشعارات:
  - Critical.
  - Warning.
  - Info.
- Actions:
  - mark as read.
  - mark all as read.
  - فلترة حسب النوع/المدى الزمني.
- تحديث غير مقيد بإعادة تحميل كامل الصفحة؛ يكتفي بتحديث عداد unread + prepend عناصر جديدة.
- يمكن pin panel في desktop وoverlay في mobile.

## 18) SignalR Live Updates

- واجهة العميل تراقب الأحداث:
  - attendance.updated
  - assignment.changed
  - readiness.recalculated
  - notification.created
- التحديث لحظيًا يجب أن يلتزم:
  - تحديث أجزاء minimal slices من الواجهة فقط (stage cards, readiness chips, unread badge).
  - عرض حالة اتصال `متصل / يعيد الاتصال / منقطع`.
  - fallback polling تدريجي عند فشل الاتصال اللحظي لفترة.
- عند استرجاع الاتصال:
  - إعادة مزامنة مختصرة لضمان عدم فقد state.

## 19) Role-based UI Visibility

- الصلاحيات الأساسية:
  - SuperAdmin: جميع العناصر.
  - Admin: عرض/تحكم إداري كامل ضمن Factory/Assignments/Notifications دون إعدادات النظام الحساسة.
  - Viewer (إن تم اعتماده): قراءة-only.
- قواعد العرض:
  - زرّات الإدارة تظهر فقط للمسموح له.
  - الروابط الحساسة مخفية/معطّلة حسب الدور.
  - إشعارات الإعدادات تظهر فقط للمستخدمين المخولين.

## 20) Status Color Semantics

- **Green = Present/Ready**
  - دلالة على عامل حاضر/مرحلة جاهزة/جاهزية جيدة.
- **Yellow = Late/Warning**
  - دلالة على تأخير/نقص جزئي/انذار قريب.
- **Red = Absent/Not Ready**
  - دلالة على غياب/تعطل كامل/حالة غير جاهزة.

التطبيق البصري في الواجهة:
- البطاقة / الشَرْط / البادج = لون حالة.
- النص يجب يحتفظ بتباين كافٍ.
- tooltip إضافي يوضح السبب (`غياب`, `تأخر`, `جاهز`).

## 21) تدفق العمل المقترح أثناء التنفيذ (مؤشرات عربية)

- الآن: تم بناء المستند كعقد UX نهائي بدون كود.
- وجدت: توافق مع نطاق المشروع ومطابقة بنية التوثيق السابقة (المستندات الرقمية من docs/04 وdocs/08 وdocs/06).
- غيرت: تم اعتماد صياغة عربية واضحة، ووحدات مرجعية لكل شاشة/تفاعل.
- التحقق: تم التأكيد على أن الملف جديد واحد فقط داخل `docs/` (markdown). 
- المخاطر: احتمال اختلاف أولوية مكونات PrimeNG بين الفرق؛ نقترح Freeze لهذه القائمة قبل تنفيذ UI.

## 22) أسئلة قرار التنفيذ

### 22.1 هل نعمل commit؟
- نعم، لأن هذا توثيق جديد ومكتمل ضمن نطاق Frontend UX فقط.

### 22.2 هل نحتاج merge إلى `main`؟
- نعم، بعد مراجعة سريعة من الفريق (2-3 موافقات) إذا كان هذا العقد جزءًا من gate التوثيق.

#### أوامر merge المقترحة
- `git checkout main`
- `git pull origin main`
- `git merge docs/frontend-ux-contracts`
- `git push origin main`

## 23) أمور قبول توثيق Frontend UX (Definition of Done)

- وثيقة عربية واضحة بدون كود.
- تغطية جميع العناصر المطلوبة في طلبك.
- الالتزام بقيود لا-code المذكورة.
- وجود تتبّع واضح للحالة اللحظية وSignalR وRole visibility.
- إدراج دلالات الألوان موحّدة (Green/Yellow/Red).
